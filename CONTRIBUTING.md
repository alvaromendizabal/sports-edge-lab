# Contribution and project ownership

[Overview](README.md) · [Publication boundary](docs/PUBLICATION_BOUNDARY.md)

Preserve completed work. Use one scoped branch and PR per change, inspect the current default-branch head and open PRs before editing, and do not overwrite concurrent track work. NFL, NCAA FBS, NBA and NCAA basketball keep independent research identities. A shared change needs an integration owner who reviews its effects across the tracks.

Public contributions should include the concrete behavior changed, evidence or meaningful tests, limits and source attribution. Reproducible demonstrations use invented inputs or data whose public redistribution is authorized. Do not commit private runtime archives, credentials, model bodies, licensed source responses, exact active recipes or unissued live forecasts. Rounded retrospective reports require the explicit track-specific publication scope.

## Review contract

- Keep frozen-original monitoring, rolling reconstruction and genuinely issued forecasts distinct.
- State exact events, horizons, targets, ties and settlement before comparing metrics.
- Never relabel current-season selection as prospective validation.
- Preserve failed experiments and completed receipts; count new and restored work separately.
- Run the affected unit, deterministic-page, browser and notebook checks. Merge only after checking the exact PR head and current base. Never bypass a required review or force-push another project's branch.
- Public pages are universally professional. Keep personal outreach and recruiting conversations outside the repository.

A public documentation update does not authorize provider spending, infrastructure changes, new source rights or wagers. Published source and a deployed website are separate deliverables.
