## Views

- `?view=slate&clock=T120`: Sunday/Monday filter, team search, kickoff/probability sorting and explicit selected information-clock views. T120 is the best usable dated snapshot; T60 is an unavailable current-input audit unless independently supplied with qualified data.
- `?view=circa`: both sides of every remaining game. The view is titled **Circa Million Picks & Performance Dashboard**. A side can be added to the five-game research card only when its official line, cover probability and push probability are present and internally consistent. Opposite selections from the same game replace each other.
- `?view=performance`: metric-specific nominated leaders, annual scores, game counts and horizon filtering.
- `?view=cards&type=games&clock=T120&page=1`: three games per 390-pixel phone card, with direct-link sharing, pagination and swipe support.
- `?view=cards&type=circa&page=1`: six paired games (twelve sides) per phone card, with line, cover, push and expected points. The Circa distribution is independent of the selected point-forecast clock.

Game cards have four pages and Circa cards have two. Add `capture=1` to display a clean phone card, or `capture=2` to render the same design at twice the pixel size for a precise exported screenshot.

Null remains unavailable. An outright win probability never substitutes for a cover probability. Expected contest points are `cover + 0.5 × push` when both values are present. The five-game card is a local research selection; it does not submit a contest entry.

## Data contract

The authoritative snapshot is `data.json`. The top-level required fields are `games` and `performance` arrays. Optional metadata fields include `as_of`, `performance_as_of`, `published_at`, `season`, `week`, `slate_date`, `edition_date`, `slate_intro`, `source_summary`, `performance_note`, `performance_method`, `circa_method`, `notes`, `sources` and `archive_links`.

| Game field | Meaning |
|---|---|
| `id` | Stable unique public game identity |
| `away`, `home` | Team abbreviations |
| `away_name`, `home_name` | Full display names |
| `away_nickname`, `home_nickname` | Optional display split override |
| `kickoff_utc` | ISO timestamp; all default display times use America/Los_Angeles |
| `kickoff_pt`, `date_pt`, `day` | Optional display/date fallbacks when schedule time is unavailable |
| `neutral` | Boolean neutral-site indicator |
| `win_home` | Probability from 0 to 1, or null |
| `win_away` | Explicit away-win probability; authoritative when present |
| `tie_probability` | Explicit tie probability; displayed separately when positive |
| `winner_target`, `winner_target_label` | Target definition and reader-facing label; can also be set at the top level |
| `margin_home` | Projected home points minus away points, or null |
| `total` | Projected combined score, or null |
| `issued_at` | Original forecast issue timestamp, or null |
| `compiled_at` | Compilation timestamp; does not establish original issuance |
| `forecast_status` | Evidence state; does not create automatic verification credit |
| `forecast_label` | Optional short, reader-facing evidence badge |
| `forecast_note`, `evidence_label`, `note`, `card_note` | Optional explanatory text; private identifiers and paths excluded |
| `model_roles` | Selected public aliases as `winner`, `margin`, `total`; each may be a string or object with `alias`, `horizon` / `information_clock` / `clock`, `objective_label`, and its original `issued_at` |
| `remaining` | False excludes a completed game from Circa selection |
| `status` | `final` or `completed` also excludes a game from Circa selection |
| `circa` | Contest evidence object, or false to exclude the game from that board |

The `circa` object supports `home_spread`, `line_verified`, `source_url`, `cover_home`, `cover_away`, `push`, `expected_home`, `expected_away` and `note`. A missing line is null. Use the exact official contest spread, not a sportsbook substitute. Probabilities use decimals. Selection requires a future/remaining game with a verified line and a complete, consistent distribution. Noninteger spreads require a zero push probability.

Explicit `win_away` is never replaced by `1 - win_home`. Complementing home probability is allowed only for a declared binary target or absent/zero tie probability. A positive tie mass without an explicit away probability leaves the away value unavailable. Winner display compares home and away directly, which preserves three-way probabilities below 50%. The legacy input aliases `probability_home`, `probability_away` and `probability_tie` are also accepted.

Performance rows support `objective`, `label`, `role_alias` (or `alias`), `model_family`, `horizon` (or `information_clock`), `validation_score`, `season_2024`, `season_2025`, `test_2026`, `games_2024`, `games_2025`, `games_2026`, `co_leaders`, `validation_label`, `status_label`, `cohort`, `note`, `format`, `digits` and `lower_is_better`. `format: "percent"` displays fractional accuracy as a percentage. Metric values remain the saved full-precision aggregates; display rounding does not regrade them.

For a descriptive newly fitted evaluation, set `is_descriptive: true` or `evaluation_class: "descriptive_new_fit"`. Optional `display_value` and `score_label` control its main score. Such rows default to **Descriptive evaluation · no promotion established**, not a validated champion label. A validation nominee and a descriptive current-season leader are separate rows. `status_label` and `note` can preserve more specific saved qualifications.

When different objectives select different information clocks, supply the clock on each `model_roles` object. The game details expose the per-objective clock and original role issue time. Phone cards also display the per-objective clock summary when supplied; a combined game card does not imply a single shared T60/T120 issue.

## Selected forecast snapshots

Set `forecast_clock_default: "T120"`. `games[].forecasts.T120` and `.T60` are complete, separate selected forecast records using the numeric, issue, compilation, role, target, status and explanatory fields above. The UI only copies those forecast fields. Identity, schedule and Circa probabilities remain on the shared game. A missing clock record clears all forecast values; it never falls back to another clock or the top-level game values. Top-level game forecasts may remain the T120 display snapshot for external consumers and structural validation.

Use `forecast_clock_meta.T120` / `.T60` objects with `label`, `as_of` and `description`. Source dates come from that explicit clock's metadata or its own uniform record `as_of`, never from the later evaluation date. An unavailable T60 record carries null numeric forecasts and an explicit qualification reason. Compilation time is labeled **Compiled**; details separately state whether original issuance is established. Phone cards show the snapshot date without manufacturing an original issue.

Use top-level `circa_source_summary`, optional `circa_note` and `circa_deadline` to explain distribution age and the contest deadline above the board. The deadline may be a text label or an object with `label` and `utc`. `circa_card_note` controls the short phone-card provenance footer; `circa_distribution_as_of` supports a date-derived fallback. Forecast clock changes never substitute point-model outputs for the saved Circa distribution.

## Newest-model comparison

The optional `newest_model_comparison` object accepts the saved comparison JSON with `models_checked`, `comparison_qualification` and `rows`. Rows use `horizon_minutes`, `objective`, `label`, `incumbent_validation`, `best_new_validation`, `new_fit_beats_incumbent`, `new_minus_incumbent`, `incumbent_2026`, `validation_selected_new_2026`, and `games_2024/2025/2026`. It renders a compact clock-selectable validation table, exact per-row support, the number of improved comparisons and separately expandable 2026 scores. Candidate selection remains based on the recorded 2024/2025 validation score; no promotion is inferred.

`sources` accepts objects with `label`, `url`, `as_of`, and `note`. `archive_links` accepts `r18` and `v10` URLs so the deployment can preserve functional archive links independently of the repository directory layout.

## Validation

```bash
node --check tracks/nfl/current/app.js
python3 tracks/nfl/current/validate_snapshot.py
```

The snapshot validator checks unique game identities, finite nullable values, probability bounds, cover/push conservation, half-point push rules, expected-point arithmetic, issue-before-kickoff ordering, linked local assets, document controls and private-path exclusions. `--allow-empty` is available only while preparing a placeholder; a populated publication uses the normal command.

Browser checks on the live Site are separate from this structural/data validation. Source publication, deployment and research refresh are different events.
