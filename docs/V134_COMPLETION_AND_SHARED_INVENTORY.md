## Measured work should guide optimization

The supervised process ran for 681.753 seconds, with a 4.134 GB peak process-tree RSS. Its owner tests took 187.401 seconds; the twelve new fit receipts sum to about 0.499 seconds. The latter excludes shared preparation, source refresh, scoring, serialization and orchestration. It is not a complete model-pipeline duration or CPU-utilization measurement.

This run supports investigating repeated preparation, source reuse and verification costs before assuming that a larger GPU will solve throughput. Focused checks can supplement a verified immutable parent, but any narrower suite needs an explicit change/dependency boundary. Skipping checks without such a boundary would simply remove evidence. No speedup is claimed by this public case study.

## A shared inventory needs explicit boundaries

The new standard-library [federation example](../examples/review_lab/shared_inventory.py) complements the existing [basketball recovery planner](HISTORICAL_ODDS_RECOVERY.md). It reuses that module's canonical hashing, identity and clock validation primitives. It does not replace its quota journal or expand its authorization.

Three invented project scopes reference two byte-distinct normalized objects. One object is shared byte-for-byte; the other carries the same normalized observation in different JSON formatting. The union reports three object references, two content objects, one request identity and one unique observation. Both source objects remain traceable. Counting filenames or raw rows would overstate usable coverage.

```bash
python -m examples.review_lab.shared_inventory
python -m unittest examples.review_lab.tests.test_shared_inventory -v
```

The federation requires every declared project scope and every referenced content object. A missing scope, unresolved object or hash mismatch blocks construction. An empty captured response remains a captured request even though it supplies no usable quote. A request missing from the declared scopes is labeled exactly that; it is not proof of universal absence and grants no dispatch permission.

Normalized observation identity preserves provider, sport, native event, ordered teams, kickoff, bookmaker, market, region, snapshot, quote time and a paired-quote content pin. Storage formatting and provenance receipts do not create additional observations. Eligibility additionally enforces pregame cutoff, quote age and explicit reuse permission. Different league namespaces never share model evaluations merely because acquisition infrastructure is shared.

The caller must authenticate inventory and event-binding receipts, validate raw provider originals, normalize them correctly and establish usage rights. Caller-supplied SHA-256 values establish byte equality, not authenticity. These invented scope receipts do not verify the owner's live S3 inventory, subscription, entitlement or current quota. The example makes no S3 or provider requests, reads no credentials, trains no models and spends no credits. A real dispatcher still requires its independent entitlement, shared-account coordination and budget checks.
