# Shared research protocol

## Distinct acceptance gates

| Gate | Evidence needed |
| --- | --- |
| Acquisition | Original response or asset, source URL, retrieval timestamp, content hash, sanitized receipt, request outcome |
| Coverage | Expected versus observed seasons, games, teams, players, fields and markets; explicit gaps and duplicate policy |
| Identity | Stable sport-scoped IDs; reviewed mappings for renamed teams, relocated franchises and transfer players |
| Availability | Event time, source publication/update time where available, retrieval time and decision cutoff |
| Features | Historical observations filtered before the cutoff; rolling transformations fitted only on past data |
| Validation | Rolling out-of-time splits, embargo where needed, training-only tuning/calibration and market baselines |
| Market evaluation | Actual quote timestamp, bookmaker, line, odds, settlement rules and reproducible price selection |
| Prospective evidence | Immutable forecasts and quotes recorded before games; outcomes appended separately |

A download can pass acquisition while failing availability or coverage. Current retrieval time proves when we captured a source; it does not prove the same information was published before a historical game. Missing vintage information must be exposed rather than silently inferred.

## Independent model comparisons

Each sport starts with regularized statistical baselines and independent team-strength models. Sport-only forecasts and market-aware forecasts are evaluated separately. Complex ensembles or distributions must improve held-out probability quality before being promoted.

Game-level sample size is the unit for outcome evaluation; millions of plays do not create millions of independent game targets. Bootstrap and uncertainty estimates should account for week and season grouping. Model selection and bet thresholds must not be tuned on the final evaluation seasons.

## Common market representation

Store sport, source event ID, bookmaker, market, selection, line, decimal odds, requested snapshot time, returned snapshot time, bookmaker update time, event start time and capture time where supplied. Preserve missingness. Requested time and returned snapshot time are separate fields.

Game winners, spread-cover decisions and over/under decisions have different labels. Pushes, ties, overtime and void rules require explicit handling. A closing reference is a benchmark; it is not an executable earlier quote.

## Reproducibility and acquisition budgets

Raw captures are immutable and content-addressed. Mutable source indexes point to verified captures; requests that fail are not cached as successes. Retries, empty responses, authentication failures and partial captures are classified separately. Provider-credit limits and AWS runtime limits are enforced independently.

Every run emits a unique run ID, timestamps, progress, usage and a compact return bundle. Preserve completed source work and repair only failed or invalid units. The operational ledger separates completed intended runs, blocking failures and nonblocking incidents. Compute estimates remain distinct from actual billed cost and provider subscriptions.

## Rights and secrets

Store paid responses in private S3 only. Keep provider credentials in encrypted runtime parameter storage, never in files committed to Git, request logs, receipts or exception bodies. Retain upstream provenance; custom ingestion and feature code do not transfer rights in third-party data.

## Sport boundaries

The five tracks share infrastructure, not labels, fitted transformations or unvalidated assumptions. College men's and women's basketball have separate identity and coverage tables. This repository does not replace the independent March Madness competition project.
